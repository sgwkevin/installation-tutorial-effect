# SANSI 泛光灯 TikTok Shop 自动剪辑要求与流程

> 本文档用于交接给其他 Codex。阅读后应直接按照本文档整理、剪辑和输出视频，不需要重新询问已经明确的固定要求。

## 1. 项目目标

- 产品：SANSI RGBW 全彩 LED Flood Light，当前主推 **80W 遥控器版本**。
- 平台：TikTok Shop。
- 发布市场：美国。
- 成片语言：自然的美式英语。
- 内容方向：万圣节家庭庭院、房屋外墙、骷髅、幽灵、蜘蛛网、墓碑等装饰场景。
- 核心目的：通过“布置前 → 安装/摆放 → 遥控切色 → 夜间完整效果 → CTA”的内容促进商品点击和成交。

## 3. 成片固定规格

| 项目 | 固定设置 |
|---|---|
| 画幅 | 9:16 竖屏 |
| 分辨率 | 1080×1920 |
| 帧率 | 30 fps |
| 时长 | 默认18秒，可在15–25秒内调整 |
| 视频编码 | H.264 |
| 像素格式 | yuv420p |
| 音频编码 | AAC，192 kbps |
| 色彩空间 | BT.709 SDR |
| 建议质量 | CRF 20，fast preset |

所有素材必须保持正确比例，禁止拉伸、压扁或使用重复拉伸的侧边填充。

## 4. 必须遵守的内容规则

1. 成片只展示一种控制方式：**遥控器或 App 二选一**。
2. 当前默认制作遥控器版本，只能出现实体遥控器，不能出现 App 页面、手机控制界面或 App 操作镜头。
3. 不出现任何价格、折扣、优惠券、评分或促销金额。
4. 未确认时，不在画面中添加功率、装数、防水等级等商品参数。
5. 不生成 AI 视频，使用用户电脑中的真实素材自动剪辑。
6. 原素材允许复用，但不同成片不能从头到尾使用完全相同的素材和时间段顺序。
7. 不使用带有外部水印、下载字幕、无授权标识或明显属于其他账号的视频。
8. BGM必须来自用户提供或确认可商用的文件；不确定版权时需要提醒用户。

## 5. 推荐剪辑结构

默认18秒结构：

| 时间 | 内容 | 建议长度 |
|---:|---|---:|
| 0–2s | 夜间最终效果先行，配强钩子 | 2s |
| 2–4s | 白天搭建或布置过程 | 2s |
| 4–6s | 泛光灯落地、插电、调整角度 | 2s |
| 6–8s | 实体遥控器切换颜色 | 2s |
| 8–14s | 红、绿、蓝、紫等不同效果快速组合 | 6s |
| 14–16s | 房屋或庭院整体大景 | 2s |
| 16–18s | 正常亮度效果画面＋CTA | 2s |

使用硬切和紧凑节奏即可，不需要为了复杂转场拖慢制作。

## 6. 标题与英文文案规范

- 标题必须在前2秒出现。
- 使用粗体白字或白字＋橙色关键词。
- 使用黑色描边保证夜景和亮色背景上的可读性。
- 标题放在画面上方的 TikTok 安全区域。
- 文案尽量短、直接、有好奇心或反差感。
- 用户指定标题时必须保持原意和完整措辞，可以分行，但不能擅自漏词。

已使用标题示例：

```text
WHATEVER YOU DO,
DON’T LET YOUR KIDS
SEE THESE THIS HALLOWEEN! 🎃
```

其他可用短文案示例：

```text
BUILD THE SCARE
SET IT. AIM IT.
PICK A COLOR
RED. GREEN. PURPLE.
MAKE YOUR YARD
THE MAIN EVENT
READY TO GLOW?
```

## 7. CTA固定规范

结尾不添加黑色底板或黑色蒙版，直接在正常视频画面上显示 CTA。

在 `1080×1920` 画布上使用：

- 文案：`TAP TO SHOP`
- 字体：粗体，约54 px。
- 颜色：橙色 `#FF7A00`。
- 黑色描边：约5 px。
- 位置：约 `x=60, y=830`。
- 在文字下方加入明显的橙色向下箭头，箭头约位于 `y=920`。
- CTA整体位于左侧中下区域，但必须高于 TikTok 播放控制区和商品卡区域。
- 结尾画面保持正常亮度，禁止视觉淡出至黑色；BGM可以单独淡出。

## 8. 夜景与HDR处理规则

### 8.1 原因

iPhone HDR/HLG 夜景转成 SDR 后，容易出现：

- 灯具高光非常亮，但周围环境被压暗；
- 红光场景暗部细节不足；
- 骷髅、草地、房屋或装饰物看不清；
- 统一套用一组滤镜后，不同镜头亮度差异仍然明显。

### 8.2 固定处理原则

1. 夜景必须逐镜头检查和调色，不能所有夜景统一套用完全相同的参数。
2. 每个选用的夜景镜头至少抽取一张代表帧检查。
3. 优先提升阴影和中间调，同时保护灯具和装饰灯高光。
4. 万圣节颜色应鲜艳、清楚，红、绿、蓝、紫不能发灰。
5. 如果调整后主体仍然看不清，应跳过暗区间或更换更清楚的素材。
6. 禁止在画面上添加黑色滤镜、暗色蒙版或结尾黑屏。

普通夜景可从以下参数开始：

```text
brightness=0.04
gamma=1.10
saturation=1.12
```

灯具很亮、环境很暗的高反差镜头可从以下参数开始：

```text
brightness=0.07
gamma=1.18
saturation=1.15
contrast=1.03
```

这些是起点，不是所有镜头必须套用的固定滤镜。如果灯光过曝或颜色失真，应适当降低参数。

建议的 FFmpeg HDR转SDR和调色链：

```text
zscale=t=linear:npl=100,
format=gbrpf32le,
zscale=p=bt709,
tonemap=tonemap=hable:desat=0,
zscale=t=bt709:m=bt709:r=tv,
format=yuv420p,
eq=brightness=0.07:gamma=1.18:saturation=1.15:contrast=1.03
```

## 9. 素材去重与打标规则

维护以下两个文件：

```text
material-tags.json
usage-history.json
```

### material-tags.json

记录素材或可用时间段的：

- 文件路径；
- 开始与结束时间；
- 场景类型；
- 白天/夜间；
- 颜色；
- 是否出现遥控器；
- 是否出现 App；
- 是否适合作为开头钩子；
- 清晰度和使用备注。

### usage-history.json

每次成片后记录：

- 成片编号和路径；
- 使用的控制方式；
- 每个镜头的源文件；
- 每个镜头的源时间段；
- 镜头顺序和用途。

新视频至少应改变以下内容中的三项：

- 开头素材或时间段；
- 搭建/安装镜头；
- 遥控器镜头；
- 灯效镜头顺序；
- 结尾大景；
- 标题文案和节奏。

与任何已有视频的完全相同“文件＋时间段”重合比例应不高于70%。只换字幕、但整条画面顺序不变，不算新视频。

## 10. BGM规则

- 从用户的 BGM 文件夹选择音乐。
- 裁剪到与成片完全相同的时长。
- 不允许结尾出现多余音乐或黑屏后音乐继续播放。
- 建议音乐音量约为原音量的50%–55%。
- 结尾最后0.6秒只淡出音频，不淡出视频画面。
- 防止削波，建议最终峰值低于 `-1 dB`；当前项目成片约 `-4.7 dB`。

## 11. 自动剪辑执行流程

### 第一步：扫描素材

1. 扫描素材目录下的 MOV、MP4、M4V和音频文件。
2. 使用 `ffprobe` 获取时长、分辨率、帧率、编码和音轨。
3. 排除0字节、损坏、无法解码或疑似无授权的素材。
4. 检查用户是否新增加了素材。

### 第二步：快速选材

1. 优先查看已经打标的可用素材。
2. 对未看过的候选素材抽取代表帧或制作联系表。
3. 确认遥控器素材不包含 App。
4. 选择与历史视频不同的开头、过程和结尾组合。

### 第三步：建立分镜

生成：

```text
segments-vN.json
storyboard-vN.json
storyboard-vN.md
```

分镜至少记录：时间、文案、源文件、源时间段、画面用途、调色要求、CTA和待处理问题。

如果用户已经说“继续做”“可以剪辑”或“开始生成”，视为已经授权执行，不需要再次停下来等待确认。

### 第四步：去重检查

将新分镜与 `usage-history.json` 对比。不得与旧成片使用完全相同的全片镜头序列。

### 第五步：渲染

1. 使用 FFmpeg 按时间段裁剪并拼接。
2. 保持画面比例，输出1080×1920。
3. 对夜景逐镜头应用不同调色参数。
4. 添加英文标题、短字幕和CTA。
5. 添加并裁剪BGM。
6. 输出H.264/AAC MP4。

### 第六步：快速但必要的QA

只做一次完整关键检查，避免反复追求不影响观看的小细节：

1. 抽查开头、每个夜景镜头中点和结尾。
2. 确认暗场主体看得清、颜色鲜艳。
3. 确认没有 App、价格、水印和意外文字。
4. 确认标题没有漏词、超出画面或被裁切。
5. 确认CTA位置正确。
6. 确认无黑屏、无黑色蒙版、无视觉淡出。
7. 使用 `ffprobe` 检查规格。
8. 使用 `blackdetect` 检查意外黑段。
9. 检查BGM时长和峰值。

只有出现以下关键问题才重新渲染：

- 标题错误或漏词；
- 夜景明显看不清；
- 出现 App、价格、水印或错误产品；
- CTA位置错误；
- 黑屏、缺音频、比例错误或文件损坏。

### 第七步：归档与记录

1. 将最终成片复制到 `D:\视频素材\月.日`。
2. 不覆盖同名文件。
3. 更新 `material-tags.json` 和 `usage-history.json`。
4. 保存分镜、渲染脚本和QA记录。
5. 将最终成片绝对路径交给用户。

## 12. 必装工具

### 必需

#### FFmpeg 和 FFprobe

用于读取、裁剪、调色、拼接、添加文字/BGM、编码和QA。

Windows可使用：

```powershell
winget install --id Gyan.FFmpeg -e
```

安装后检查：

```powershell
ffmpeg -version
ffprobe -version
```

#### PowerShell

Windows自带，可用于运行自动化脚本、归档、素材去重和记录更新。建议使用 PowerShell 7，但Windows PowerShell也可执行大部分脚本。

### 推荐安装

#### Python 3 和 Pillow

用于生成素材缩略图、联系表和批量视觉检查，不参与正式视频编码。

```powershell
winget install --id Python.Python.3.12 -e
python -m pip install pillow
```

### 建议安装的 Codex Skills

- `auto-cut`：负责分镜、素材确认、自动剪辑和QA流程。
- `installation-tutorial-effect`：保存本项目的安装、遥控、灯效、CTA、亮度和素材去重规则。

如果另一台 Codex 没有第二个 Skill，也可以直接将本文档作为项目指令执行。

### 非必需工具

- Video2X：仅用于视频超分辨率，不是自动剪辑必需工具。
- Clipcat：偏TikTok商品研究、爆款参考和AI内容生成，不是本地素材自动剪辑的必需工具。
- CapCut：可用于人工复查或手动修改，但FFmpeg自动化流程不依赖CapCut。
- Remotion/HyperFrames：只有需要复杂动画时才使用；普通带货视频不必安装。

## 14. 给执行Codex的效率要求

- 用户重视出片速度，不要为了无关紧要的画面差异反复渲染。
- 先确保标题、亮度、控制方式、价格、CTA、黑屏和文件规格这些关键项正确。
- 发现单个暗镜头时，只调整或替换该镜头，不要推翻整条剪辑。
- 工作超过一分钟时，给用户简短进度更新。
- 完成后直接提供最终视频路径，不要只汇报“正在处理”。
